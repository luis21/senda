# Senda Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Ejecución en esta sesión con un solo agente, según la preferencia de Luis.

**Goal:** Obtener primero una compilación reproducible de Chromium para Windows y después incorporar las funciones de Senda en entregas verificables.

**Architecture:** Mantener herramientas y manifiesto de revisión en este repositorio; conservar el árbol externo de Chromium en un directorio de compilación sin espacios. Aplicar cambios pequeños sobre una revisión fijada, manteniendo el sandbox y el aislamiento de sitios.

**Tech Stack:** Chromium, C++, GN, depot_tools, autoninja/Siso y herramientas oficiales de Windows; PowerShell para preparación y diagnóstico.

**Spec:** ../specs/2026-10-31-senda-design.md

## Global Constraints

- Windows 11 x64 como primer objetivo de compilación y prueba.
- No añadir un contenedor Electron.
- Sin telemetría propia ni envío automático de informes de fallos.
- Bloqueador integrado y activo por defecto, independiente de una extensión instalada por el usuario.
- No garantizar compatibilidad con todas las extensiones ni asumir acceso automático a Chrome Web Store.
- No desactivar sandbox ni aislamiento de sitios para ahorrar memoria.
- No afirmar ahorro de RAM sin comparación reproducible con Chrome.
- Primera entrega técnica local; publicación condicionada a firma, actualización y mantenimiento de seguridad.

## Review Focus

1. Disco insuficiente o memoria desconocida: detener preparación pesada con diagnóstico concreto, sin descargar parcialmente cientos de dependencias.
2. Rutas con espacios o revisiones incorrectas: rechazar antes de aplicar parches.
3. Perfiles existentes: no abrir ni modificar el perfil de Chrome; usar un directorio exclusivo de Senda.
4. Sitios rotos por bloqueo o suspensión: excepción reversible y conservación de actividades detectables.
5. Actualización fallida: conservar una versión funcional y no aceptar código ni listas sin validar.

## Organización prevista

- `tools/Test-SendaEnvironment.ps1`: diagnóstico de recursos y herramientas, sin instalar ni cambiar configuración global.
- `tools/Initialize-SendaChromium.ps1`: preparar checkout externo solo si pasa diagnóstico.
- `tools/Build-Senda.ps1`: verificar revisión, generar y compilar.
- `tools/Start-Senda.ps1`: abrir compilación con perfil exclusivo.
- `config/chromium.json`: origen, commit exacto y requisitos de la revisión seleccionada.
- `config/args.dev.gn`: configuración GN de desarrollo x64 sin marca Google Chrome.
- `patches/series`: orden explícito de cambios sobre Chromium; no incluir parches hasta verificarlos contra el checkout.
- `docs/build/windows.md`: instrucciones reproducibles y límites conocidos.
- `docs/validation/`: resultados de compilación, pruebas y mediciones; excluir perfiles y secretos.

## Plan ejecutable del primer hito: base de compilación

### Tarea 1: diagnóstico reproducible

**Archivos:** crear `tools/Test-SendaEnvironment.ps1`, `tests/Test-SendaEnvironment.Tests.ps1` y `docs/build/windows.md`.

**Interfaz:** `Test-SendaEnvironment.ps1 -CheckoutRoot <ruta> -AsJson` produce JSON con `ready`, `checks` (name, status, detail) y código de salida 0 si está listo, 1 si falta un requisito. Un dato desconocido no equivale a requisito aprobado.

- [ ] Escribir pruebas con datos simulados: 53,6 GB falla el mínimo de 100; 100 GB lo satisface; ruta con espacios falla; RAM desconocida impide declarar listo; herramientas ausentes aparecen identificadas.
- [ ] Ejecutar pruebas con Pester disponible en el entorno y comprobar que fallan porque aún no existe el diagnóstico. Si Pester no está instalado, usar un arnés PowerShell aislado sin instalar módulos globales.
- [ ] Implementar consultas de solo lectura con errores explícitos; permitir comprobar otra unidad sin suponer C:. No enumerar datos personales ni cambiar Defender, PATH global o configuración de Git.
- [ ] Ejecutar las pruebas y el diagnóstico real; guardar resumen fechado en `docs/validation/environment.md`.
- [ ] Revisar diff y guardar el cambio en Git si hay identidad local configurada; no inventar autor.

### Tarea 2: revisión fijada y preparación

**Archivos:** crear `config/chromium.json`, `tools/Initialize-SendaChromium.ps1`, pruebas de preparación y ampliar `docs/build/windows.md`.

**Interfaces:** consumir el diagnóstico de tarea 1; manifiesto con `repository`, `revision` (commit de 40 caracteres), `version`, `requirements` y referencia oficial. Inicializador recibe `-CheckoutRoot` y `-ManifestPath`; no descarga si falla el diagnóstico.

- [ ] Consultar fuentes oficiales para elegir una versión estable mantenida y resolver su commit exacto. Registrar requisitos de esa revisión; no compilar main flotante.
- [ ] Probar que diagnóstico fallido impide invocar Git/fetch, que una revisión divergente se rechaza y que una segunda ejecución no sobrescribe cambios locales.
- [ ] Implementar preparación según instrucciones de esa revisión, con depot_tools, configuración limitada al proceso/repositorio y comprobación de salida de cada comando. Ejecutar inicialización de gclient mediante cmd como indica Chromium.
- [ ] Con recursos suficientes y ruta permitida sin espacios, obtener código y dependencias; validar commit con `git rev-parse HEAD` y estado de gclient. Antes de ello, esta tarea permanece bloqueada: no crear un checkout ficticio.
- [ ] Documentar revisión y herramientas reales; comprobar diff antes de guardar en Git.

### Tarea 3: compilar y abrir la base

**Archivos:** crear `config/args.dev.gn`, `tools/Build-Senda.ps1`, `tools/Start-Senda.ps1` y pruebas de validación de argumentos.

**Interfaces:** compilador recibe `-CheckoutRoot` y `-Configuration Dev`; lanza `gn gen out/SendaDev` y `autoninja -C out/SendaDev chrome`. Lanzador recibe `-CheckoutRoot` y `-UserDataDir`; solo acepta un perfil exclusivo de desarrollo.

- [ ] Probar rechazo de checkout ausente, commit distinto, rutas de perfil Chrome y salida de compilación fallida. No lanzar ejecutable viejo tras un fallo.
- [ ] Implementar argumentos GN verificados con la revisión: x64, `is_chrome_branded=false`, compilación componente de desarrollo y símbolos reducidos; conservar seguridad y evitar servicios remotos internos de Google.
- [ ] Generar y compilar; registrar comandos, commit, versión de herramientas, duración y resultado en `docs/validation/baseline-build.md`.
- [ ] Abrir con perfil exclusivo y comprobar HTTPS, dos pestañas, descarga desde un servidor controlado y persistencia de un marcador tras reinicio.
- [ ] Documentar que aún es Chromium base y no Senda terminado. Guardar cambios revisados.

## Hitos posteriores y orden de implementación

Estos son alcances y criterios de aceptación, no planes de código contra archivos aún inexistentes. Tras disponer del checkout, cada hito recibe un plan acotado con rutas e interfaces reales antes de modificar Chromium.

### Hito 2: identidad e interfaz

Crear parches de identidad Senda, perfil y registro de aplicación propios; nueva pestaña local con buscador configurable y accesos editables; temas claro, oscuro y sistema. Mantener navegación, marcadores, descargas y ventanas privadas. Validar teclado, contraste, escalado, persistencia y ausencia de acceso al perfil de Chrome. Elegir paleta, tipografía e icono mediante una propuesta visual antes de producir recursos finales.

### Hito 3: privacidad y bloqueo

Investigar una biblioteca mantenida y licencias de listas; documentar elección y puntos de integración reales. Implementar filtrado de solicitudes, reglas cosméticas, actualización validada con última lista funcional, panel por sitio y excepciones. Pruebas con servidor controlado: bloquear anuncio/rastreador, permitir recurso legítimo, recuperar sitio mediante excepción y rechazar lista corrupta. Auditar conexiones salientes y telemetría heredada; conservar protección contra sitios maliciosos con dependencias documentadas.

### Hito 4: extensiones y compatibilidad

Verificar instalación, permisos y actualización de extensiones representativas, incluyendo una con contenido inyectado y otra con permisos opcionales. Comprobar convivencia con bloqueo nativo y ventanas privadas. Investigar acceso y condiciones de Chrome Web Store, DRM y códecs; comunicar incompatibilidades verificadas sin atribuir al navegador capacidades no probadas.

### Hito 5: memoria

Adaptar descarte de pestañas existente y excepciones; verificar reproducción, llamadas y trabajo sin guardar detectable. Comparar compilaciones optimizadas equivalentes, no Senda debug contra Chrome release. Usar mismos perfiles limpios, páginas, extensiones y hardware; medir árbol de procesos, memoria privada, CPU y reactivación en varias repeticiones. Registrar resultados y limitaciones; no fijar porcentajes de ahorro antes de línea base.

### Hito 6: distribución pública

Separar instalación Senda de Chrome, respetar elección de navegador predeterminado y comprobar desinstalación. Preparar firma, canal de actualización autenticado, rollback, licencias y procedimiento para parches urgentes de Chromium. Probar actualizaciones interrumpidas o alteradas. No publicar ni contratar infraestructura hasta disponer de artefactos revisables y autorización para las acciones externas correspondientes.

## Revisión del plan

Diseño cubierto por primer hito más hitos 2–6. Las decisiones dependientes del código no se disfrazan de parches ya diseñados. El siguiente trabajo útil es el diagnóstico automatizado; descargar y compilar requiere resolver disco, herramientas, memoria verificable y ubicación sin espacios.
